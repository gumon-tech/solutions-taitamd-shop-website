# ข้อมูลทีมบนเว็บ — `data/team.json`

**ระบบร้าน (KBOT) เป็นเจ้าของข้อมูล ห้องเว็บเป็นเจ้าของหน้าตา** ระบบเปิด PR แก้ไฟล์นี้ ห้องเว็บรันด่านแล้ว merge
ระบบไม่ push `main` ไม่ merge เอง · ทางเดียวกับ `data/promotions.json` และ `data/vacancies.json`

รีโปนี้เป็น **public** ⇒ ทุกอย่างในไฟล์นี้อ่านได้จากภายนอกที่ `raw.githubusercontent.com`
ไฟล์นี้มีเฉพาะคนที่ยังทำงานอยู่และยินยอมให้ขึ้นเว็บแล้ว · ลาออกหรือถอนยินยอม ระบบเปิด PR เอาแถวกับรูปออกเอง

## ระดับไฟล์

| ช่อง | ความหมาย |
|---|---|
| `updated_at` | เวลาที่แก้ล่าสุด ISO UTC (ไว้ให้คนอ่าน ระบบไม่ใช้ตัดสิน) |
| `members` | รายการคน · ลำดับที่แสดงมาจากช่อง `order` ไม่ใช่ลำดับในไฟล์ |

## ระดับคน

| ช่อง | บังคับ | ความหมาย |
|---|---|---|
| `id` | ใช่ | ตัวพิมพ์เล็ก ตัวเลข และยัติภังค์เท่านั้น · เป็นชื่อไฟล์รูปและสมอของหน้า ⇒ ห้ามเปลี่ยนหลังขึ้นแล้ว |
| `display_name` | ใช่ | ชื่อที่เจ้าตัวเลือกให้แสดง |
| `role` | ใช่ | บรรทัดบทบาท เช่น `NVQ Assessor · Team Leader & Manager` · **เพิ่มจากที่ KBOT เสนอ** เพราะหน้าเว็บวันนี้แสดงบทบาทแยกจากความถนัดอยู่แล้ว ถ้าไม่มีช่องนี้หน้าจะเสียข้อมูลที่มีอยู่ |
| `bio` | ใช่ | **ภาษาอังกฤษเท่านั้น** เพราะทั้งเว็บเป็นอังกฤษล้วน · **ไม่เกิน 200 ตัวอักษร** (ของเดิมในหน้า `/signature/` ยาว 60 ถึง 90 ตัว ⇒ 200 มีที่เหลือโดยไม่เปิดให้ใส่ย่อหน้า) |
| `languages` | ใช่ | ไม่เกิน 5 รายการ |
| `specialties` | ใช่ | ไม่เกิน 6 รายการ |
| `photo` | **ไม่บังคับ** | path ใต้ `/images/team/` และเป็น `.jpg` · **จงใจให้ไม่บังคับ** เพราะคนที่ยินยอมให้ลงชื่อแต่ไม่ยินยอมให้ลงรูป ต้องขึ้นเว็บได้ ⇒ ไม่มีรูปก็แสดงได้ |
| `order` | ใช่ | ตัวเลข น้อยขึ้นก่อน |

**ช่อง `alt` ของรูป หน้าเว็บ render เอง ระบบไม่ต้องส่ง** เหตุผลสองข้อ หนึ่ง ถ้อยคำ alt ขึ้นกับบริบทของหน้าซึ่งเป็นของห้องเว็บ
สอง ช่องข้อความอิสระเพิ่มอีกช่อง คือทางเพิ่มอีกทางที่ข้อความจะไหลขึ้นหน้าสาธารณะ

## ช่องที่ห้ามมี และด่านบังคับให้

ไฟล์นี้ **ห้ามมีชื่อตามกฎหมาย วันเกิด ที่อยู่ เบอร์ อีเมล ข้อมูลการเงิน และเลขพนักงานทุกชนิด**
`lib/team.ts` ตรวจ **ตามชื่อช่อง** ไม่ใช่ตามค่า แล้วทำให้ `next build` ล้มถ้าเจอ
```
legal_name · full_name · surname · last_name · dob · date_of_birth · birthday
address · postcode · phone · mobile · email · nin · ni_number · national_insurance
bank · account · sort_code · salary · pay · staff_number · employee_number
treatwell_id · treatwell_staff_id
```
ฝั่ง KBOT มีด่านของตัวเองที่ปฏิเสธก่อนเปิด PR อยู่แล้ว ⇒ **ด่านนี้คือปลายอีกข้างของรั้วเดียวกัน**
เพราะกติกาที่บังคับข้างเดียว คือกติกาจนกว่าจะมีคนแก้อีกข้าง

## รูป

```
ที่อยู่       public/images/team/<id>.jpg   หนึ่งรูปต่อคน ชื่อไฟล์ตรงกับ id
ชนิด        jpg เท่านั้น  (เว็บเสิร์ฟรูปดิบ ไม่ย่อให้ ⇒ ระบบย่อมาก่อนส่ง)
ขนาด        600 x 600  จัตุรัส 1:1
เพดานไฟล์    80 KB ต่อรูป
```
เหตุผลของตัวเลข หน้าแสดงรูปราว 300 px ⇒ 600 px คือ 2 เท่าสำหรับจอความละเอียดสูง
และถ้าทีมมี 8 คน 80 KB ต่อรูป = ราว 640 KB ทั้งหน้า ซึ่งเป็นเพดานที่ยังรับได้สำหรับหน้าที่เสิร์ฟรูปดิบ
ถ้าทีมโตเกิน 10 คน ให้ทบทวนตัวเลขนี้ใหม่ อย่าปล่อยให้โตตามจำนวนคนเงียบ ๆ

## ด่านไฟล์กำพร้า — ข้อตกลงที่ยืนยันแล้ว

`scripts/check-orphan-assets.mjs` สแกน `data/` ด้วย ⇒ path ใน `photo` นับเป็นการอ้างถึง
**หน้าเว็บจะอ้างรูปทีมผ่านช่อง `photo` ในไฟล์นี้เท่านั้น ไม่ hardcode path รูปทีมใน `.tsx`**
เพราะถ้า hardcode ด่านจะเห็นสองที่อ้าง แล้วตอนระบบลบรูป build จะล้ม

**ข้อยกเว้นที่ต้องรู้** `public/images/tour/team-group.jpg` เป็นรูปหมู่ที่หน้า `/signature/` ใช้อยู่
อยู่ใต้ `images/tour/` ไม่ใช่ `images/team/` ⇒ **อยู่นอกโซนของระบบ ระบบไม่ต้องแตะและห้ามลบ**

## เกณฑ์ตรวจ PR ของไฟล์นี้

```
1 ด่านครบสี่ตัว   npm run build && npm run lint && npm run check:css && npm run check:assets
2 รูปที่เพิ่ม      ต้องมีแถวที่ photo ชี้ถึง · รูปที่ไม่มีแถวอ้างถึง ต้องถูกลบใน PR เดียวกัน
3 แถวที่เอาออก    รูปของแถวนั้นต้องถูกลบใน PR เดียวกัน
4 ขอบเขต        PR ต้องแตะเฉพาะ data/team.json และ public/images/team/ เท่านั้น
                 แตะไฟล์นอกสองที่นี้ ⇒ ตีกลับโดยไม่ต้องถกเหตุผล
5 ถ้อยคำ         bio กับ role เป็นถ้อยคำที่คนนอกอ่าน ⇒ ถ้าอ่านแล้วเป็นคำกล่าวอ้างเรื่องคุณวุฒิหรือผลลัพธ์
                 ห้องเว็บจะถามก่อน merge ไม่ merge แล้วค่อยถาม
```
