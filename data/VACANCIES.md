# ตำแหน่งที่เปิดรับ — `data/vacancies.json`

ไฟล์เดียวที่บอกว่าร้านเปิดรับตำแหน่งอะไรอยู่ · หน้า `/careers/` อ่านไฟล์นี้ และ **ระบบของ KBOT อ่านไฟล์เดียวกัน**
ทาง `raw.githubusercontent.com/.../main/data/vacancies.json` แบบเดียวกับที่อ่าน `promotions.json` อยู่แล้ว
⇒ เว็บกับบอตพูดตรงกันโดยไม่มีสำเนาที่สอง · เปลี่ยนชื่อช่องต้องตกลงกับ KBOT ก่อน

รีโปนี้เป็น **public** (วัดด้วย `gh repo view`) ⇒ ทุกอย่างในไฟล์นี้ รวมรายการ `draft` อ่านได้จากภายนอก
**ห้ามใส่ชื่อพนักงาน ข้อมูลผู้สมัคร หรืออะไรที่ยังไม่พร้อมให้คนนอกเห็น**

## ระดับไฟล์

| ช่อง | ความหมาย |
|---|---|
| `updated_at` | เวลาที่แก้ล่าสุด ISO UTC (ไว้ให้คนอ่าน ระบบไม่ใช้ตัดสิน) |
| `note` | ประโยคใต้หัวข้อ ไม่บังคับ · **ไม่มีตำแหน่งเปิด = ถอดช่องนี้ออก หรือส่งสตริงว่าง** สองรูปค่าเท่ากัน |
| `vacancies` | รายการตำแหน่ง เรียงตามลำดับที่แสดง |

## ระดับตำแหน่ง (ทุกช่องบังคับ)

| ช่อง | ความหมาย |
|---|---|
| `code` | รหัสไม่ซ้ำ เช่น `V-FOH-01` |
| `group` | `A` ผู้เริ่มต้น · `B` มีคุณวุฒิแล้ว · `C` ระดับสูง (นิยามอยู่ใน `docs/plans/STAFFING-AND-CAREERS-2026-10-20.md` ข้อ 6.3) |
| `title` `summary` | ชื่อตำแหน่งและคำอธิบายสั้น |
| `duties` | สิ่งที่ทำจริงในแต่ละวัน (รายการข้อความ อย่างน้อยหนึ่งรายการ) |
| `essential` | คุณสมบัติขั้นต่ำ · **คุณวุฒิให้ระบุระดับ ไม่ใช่ชื่อประกาศนียบัตรอย่างเดียว** เพราะคนที่จบคนละรุ่นถือคนละชื่อที่ระดับเดียวกัน |
| `desirable` | ที่อยากได้เพิ่ม (รายการว่างได้) |
| `council_registration` | `true` เมื่อผู้ที่ได้ตำแหน่งต้องจดทะเบียนกับสภา Islington ก่อนลงมือ · **ต้องบอกผู้สมัครด้วยว่าใช้เวลาอย่างน้อย 21 วัน เพราะกระทบวันเริ่มงานจริง** |
| `posted` `closes` | วันที่ `YYYY-MM-DD` · แสดงตั้งแต่เที่ยงคืนต้นวัน `posted` ถึงเที่ยงคืนท้ายวัน `closes` เวลาลอนดอน |
| `closes_label` | วันปิดรับแบบคนอ่าน |
| `status` | `live` แสดงตามช่วงวัน · `draft` ยังไม่แสดง · `closed` เก็บเป็นประวัติ |

## ช่องที่ห้ามมี และด่านบังคับให้

**ผู้สั่งงานเคาะ 2026-10-20 ว่าเว็บจะไม่แสดงค่าตอบแทนและรูปแบบการจ้าง** ผู้สมัครไปคุยกับทีมผู้บริหารเอง
กติกาที่คนต้องจำคือกติกาที่กลับมา จึงทำเป็นด่าน: ใส่ช่องใดช่องหนึ่งต่อไปนี้แล้ว `next build` ล้มทันที
```
pay · salary · wage · rate · employment_type · employmentType · status_of_engagement
```
และคำเคาะ `L-3` ห้ามใช้คำว่า self-employed เช่าเก้าอี้ หรือแบ่งเปอร์เซ็นต์ ในถ้อยคำด้วย จนกว่าจะเคาะข้อ 4.6

## ด่านปฏิทิน

| เงื่อนไขที่ทำให้ `next build` ล้ม | เหตุผล |
|---|---|
| ตำแหน่ง `status: "live"` ที่เลยเที่ยงคืนท้ายวัน `closes` แล้ว | ประกาศงานที่ปิดไปแล้วแต่ยังอยู่บนเว็บ แย่กว่าโปรหมดอายุ เพราะมีคนเสียเวลาสมัคร |
| มี `note` ที่ไม่ว่าง ทั้งที่ไม่มีตำแหน่งไหนเปิดอยู่ | ประโยคเก่าจะโผล่พร้อมตำแหน่งใหม่ใบแรก |

**พิสูจน์แล้ว 2026-10-20 ว่าฟ้องจริงทั้งสองข้อ** ตอนที่หน้า `/careers/` เริ่ม import ตัวอ่าน
รันกับไฟล์ที่ตั้ง `posted: 2026-09-01` `closes: 2026-09-30` และ `status: live` หนึ่งรายการ
build ล้มพร้อมข้อความ ``V-FOH-01: `status` is still "live" but the position closed on 2026-09-30 — set it to "closed"``
แล้วปิดทุกตำแหน่งโดยทิ้ง `note` ไว้ build ล้มพร้อมข้อความ ``(file): `note` is still set while nothing is open``
จากนั้นคืนไฟล์จริงแล้ว build ผ่าน ⇒ ไม่ใช่ด่านที่ผ่านตลอด
