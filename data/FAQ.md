# คำถามที่พบบ่อย — `data/faq.json`

คำถาม-คำตอบทุกชุดบนเว็บอยู่ไฟล์นี้ · ข้อมูล structured data `FAQPage` สร้างจากรายการเดียวกัน (ข้อความที่คนอ่านกับที่ Google อ่านจึงไม่แยกกัน)
ไฟล์ผิดรูป ⇒ `next build` ล้ม ⇒ deploy ไม่เกิด · ตัวตรวจอยู่ที่ `lib/faq.ts`

## โครง

| ช่อง | ความหมาย |
|---|---|
| `shop` | ชุดของร้าน แสดงบนหน้าแรกและหน้า massage-kings-cross |
| `massage_expectation` | คำตอบ "What should I expect during a massage?" บนหน้า services · ย่อหน้าแรกต้องตรงกับ `SITE.standardsNotice` ใน `lib/site.ts` ทุกตัวอักษร (ตัวตรวจฟ้องถ้าไม่ตรง) |
| `pages` | ชุดต่อหน้า ใช้ชื่อโฟลเดอร์ของหน้า: `nails-kings-cross` `facial-kings-cross` `waxing-kings-cross` `lash-extensions-kings-cross` `deep-tissue-massage-kings-cross` `signature` `services` |

## แต่ละคำถาม (`id` `q` `a` ครบทุกช่อง · `status` ใส่หรือไม่ใส่ก็ได้ · ไม่มีช่องอื่น)

| ช่อง | ความหมาย |
|---|---|
| `id` | ตัวพิมพ์เล็ก ตัวเลข ยัติภังค์ ไม่เกิน 60 · ไม่ซ้ำในชุดเดียวกัน |
| `q` | คำถาม ไม่เกิน 160 ตัวอักษร |
| `a` | คำตอบ ข้อความเดียว หรือรายการย่อหน้า (ไม่เกิน 6) · ย่อหน้าละไม่เกิน 700 ตัวอักษร |
| `status` | ไม่บังคับ · `live` แสดง (ไม่ใส่ = `live`) · `hidden` ซ่อน: ไม่แสดงบนหน้า และไม่อยู่ใน `FAQPage` · ค่าอื่น ⇒ build ล้ม |

`status` ใช้ได้กับคำถามในชุด `shop` และชุดของแต่ละหน้าใน `pages` เท่านั้น · `massage_expectation` ไม่มีช่องนี้ (แสดงเสมอ)
คำถามที่ซ่อนยังถูกตรวจรูปและ token ทุกข้อ ยังครอง `id` และลำดับของมัน · ห้ามซ่อนทุกข้อในชุดเดียว (หน้าจะเหลือแผงเปล่า และ `FAQPage` ว่างที่ Google ฟ้อง) ⇒ build ล้ม

ทุกข้อความ: ไม่ว่าง · ห้ามมี `<` `>` · ไม่ใช้ markdown · อ้างได้เท่าที่ร้านยืนยันแล้ว (คำตอบ FAQ คือคำสัญญาล่วงหน้า)

## ตัวแทนค่า (token)

ใส่ในคำตอบได้เฉพาะชุดนี้ build แทนค่าให้ · ใช้ token อื่น ⇒ build ล้ม

| token | ค่า | มาจาก |
|---|---|---|
| `{{hours}}` | `10:30am to 9:00pm` | `data/hours.json` |
| `{{walk_minutes}}` | `5` | `SITE.walkMinutes` ใน `lib/site.ts` |
| `{{address}}` | `72-74 Caledonian Road, King's Cross, London, N1 9DN` | `SITE.address` |

เขียนเวลาเปิดร้านเป็นตัวเลขตรง ๆ ในคำตอบไม่ได้ผล ⇒ ใช้ `{{hours}}` เสมอ จะได้ตามไฟล์ `hours.json`

## การเปลี่ยนจากระบบร้าน (shop system)

สาขา `shop-agent/faq-<id>` · ไฟล์ `data/faq.json` · workflow `.github/workflows/auto-merge-shop-agent.yml` merge เองเมื่อด่านผ่าน แล้วสั่ง deploy

ระบบทำได้ / ห้าม
- **แก้คำถามหรือคำตอบเดิม** (`q` `a`) ในชุด `shop` และชุดของแต่ละหน้าใน `pages` · `id` เดิมห้ามเปลี่ยน
- **เพิ่มคำถามใหม่** ต่อท้ายชุด (`id` ตัวพิมพ์เล็ก ตัวเลข `-` · ช่อง `id` `q` `a` และ `status` ถ้าต้องการ)
- **ซ่อนหรือเลิกซ่อน** คำถามใดก็ได้ในชุด `shop` และ `pages` (ทั้งของเดิมและที่ระบบเพิ่มเอง) ด้วยการตั้ง `status` เป็น `hidden` หรือ `live` หรือเอาช่องออก · ค่าอื่นไม่ได้ · ห้ามซ่อนจนชุดหนึ่งไม่เหลือคำถามที่แสดง
- **ห้ามลบหรือย้ายลำดับ** (เลิกแสดงให้ตั้ง `status: "hidden"` · ลบจริงต้องผ่านคน) · ห้ามเพิ่มหรือลบ key ของ `pages` (หน้าเป็นโค้ด)
- **ห้ามแตะ `massage_expectation`** (ย่อหน้าแรกคือ standards notice ถ้อยคำที่เจ้าของอนุมัติ)
- token ใช้ได้เฉพาะ `{{hours}}` `{{walk_minutes}}` `{{address}}` · วงเล็บปีกกาอื่นไม่ได้
- ข้อควรรู้: คำตอบเดิมบางข้อมีราคา (`£69`) · ระบบร้านแก้ข้อนั้นไม่ได้ถ้ายังมีราคาอยู่ (ต้องผ่านคน)

ด่านทั้งหมดเหมือนโปรโมชัน (ดู `data/PROMOTIONS.md` หัวข้อ "การเปลี่ยนจากระบบร้าน"): PR แก้ไฟล์นี้ไฟล์เดียว ·
`npm run test:shop-agent` · `check-orphan-assets` · `next build` (ตัวตรวจของไฟล์นี้ใน `lib/`) · lint · `check:css` ·
`scripts/check-shop-agent-diff.mjs faq` · และ `main` ต้องยังไม่ขยับตอน merge · ไม่ผ่านข้อใด PR ค้างไว้ให้คน พร้อมคอมเมนต์ `shop-agent-merge-failed`
ข้อความที่เพิ่มหรือแก้ต้องผ่านกติกาเนื้อหาชุดเดียวกับโปรโมชัน (ไม่อ้างผลต่อสุขภาพ · ไม่มีลิงก์ โดเมน อีเมล เบอร์โทร · อักษรอังกฤษเท่านั้น ·
ไม่มีอีโมจิหรืออักขระล่องหน · ไม่มีชื่อคนในทีม · คำเดียวไม่เกิน 24 ตัวอักษร · ห้าม `<` `>`) · **ห้ามเขียนราคาหรือสัญลักษณ์เงิน** (`£` `€` `$`) ราคาอยู่ที่ `data/services.json` ที่เดียว · คำว่า therapist ใช้ได้
ข้อความเดิมที่ไม่ได้แตะ ไม่ถูกตรวจซ้ำ
