# โปรโมชันหน้าแรก — `data/promotions.json`

แก้โปรโมชันบนหน้าแรกได้โดยแก้ไฟล์นี้ไฟล์เดียว ไม่ต้องแตะโค้ด (ผู้สั่งงานสั่งผ่าน KBOT 2026-10-14)
ระบบร้าน (KBOT) จะเปิด PR แก้ไฟล์นี้เอง · ระหว่างยังไม่มี token คนแก้ตามที่ระบบส่งให้
ชื่อช่องใช้ร่วมกับฐานข้อมูลของ KBOT ⇒ เปลี่ยนชื่อช่องต้องตกลงกับ KBOT ก่อน

รีโปนี้เป็น public (วัด 2026-10-14 ด้วย `gh repo view`) ⇒ ทุกอย่างในไฟล์นี้ รวมโปร `draft` อ่านได้จากภายนอก
ที่ `raw.githubusercontent.com/.../main/data/promotions.json` (200 · 2,443 B) ⇒ ห้ามใส่สิ่งที่ยังไม่พร้อมให้ลูกค้าเห็น
KBOT อ่านไฟล์นี้จาก URL นั้นทุก 3 ชั่วโมงเป็นทะเบียนโปร

## ระดับไฟล์

| ช่อง | ความหมาย |
|---|---|
| `updated_at` | เวลาที่แก้ล่าสุด ISO UTC (ไว้ให้คนอ่าน ระบบไม่ใช้ตัดสิน) |
| `note` | ประโยคใต้หัวข้อ ไม่บังคับ · ระวัง: ถ้าเขียนจำนวนโปรหรือวันหมดเขตไว้ ต้องแก้ให้ตรงทุกครั้งที่เพิ่มหรือถอดโปร<br>**ไม่มีโปร `live` = ถอดช่องนี้ออก หรือส่งเป็นสตริงว่าง `""`** สองรูปนี้ค่าเท่ากัน (ค่าที่มีแต่ช่องว่างก็นับว่าไม่มี) · ห้ามเก็บประโยคเก่าไว้ เพราะตอนไม่มีโปรมันไม่แสดง แล้วจะโผล่พร้อมโปรใหม่ใบแรก ตอนนี้มีด่านฟ้องแล้ว (ดูท้ายไฟล์) |
| `promotions` | รายการโปร เรียงตามลำดับที่แสดง |

## ระดับโปร (ทุกช่องบังคับ)

| ช่อง | ความหมาย |
|---|---|
| `code` | รหัสไม่ซ้ำ เช่น `P-SAUNA90` · ภาพใหม่ตั้งชื่อตามนี้ใน `public/images/campaigns/` |
| `title` `eyebrow` `detail` `offer` | ข้อความบนการ์ด · อ้างได้เท่าที่ใบปลิวหรือผู้สั่งงานให้มาเท่านั้น |
| `points` | ป้ายสั้นบนการ์ด (รายการข้อความ) |
| `message` | ข้อความ WhatsApp สำเร็จรูป · เว็บเติม `[web-C]` ให้เอง ห้ามใส่ป้ายเอง |
| `image` | path ใต้ `/images/` · ไฟล์ต้องอยู่ใน `public/` จริง · ตรวจขนาดก่อน commit (เว็บไม่ย่อรูปให้) |
| `illustrative` | `true` เมื่อเป็นภาพสร้างที่มีการทำทรีตเมนต์ · `false` สำหรับภาพจริงของร้าน (กติกา LAW `D-W22`) |
| `starts` `ends` | วันที่ `YYYY-MM-DD` · แสดงตั้งแต่เที่ยงคืนต้นวัน `starts` ถึงเที่ยงคืนท้ายวัน `ends` เวลาลอนดอน |
| `ends_label` | วันหมดเขตแบบคนอ่าน เช่น `Friday 16 October 2026` |
| `status` | `live` แสดงตามช่วงวัน · `draft` ยังไม่แสดง · `ended` เก็บไว้เป็นประวัติ ไม่แสดง |

## พฤติกรรม

- โปรขึ้นและลงเองตามนาฬิกาของผู้เข้าชม ไม่ต้อง deploy ตรงวัน · แต่โปรที่ยังไม่อยู่ในไฟล์ตอน build จะไม่ขึ้นจนกว่าจะ deploy
- **ระวัง: "ซ่อนเอง" ไม่เท่ากับ "หายจากเว็บ"** — โปรที่ `status: live` และยังไม่หมดเขตตอน build จะถูกฝังลง HTML
  แล้วซ่อนด้วยนาฬิกาฝั่งผู้เข้าชม (`PromoGate`) ⇒ หลังหมดเขต ลูกค้าไม่เห็น แต่ HTML ยังแบกข้อเสนอที่หมดอายุไว้
  (วัด 2026-10-19: apex 182,265 B มีส่วนโปรทั้งก้อน · build ที่ปิดสถานะแล้ว 159,902 B ⇒ ต่างกัน ~22 KB)
  ⇒ crawler และคนที่ปิด JS ยังอ่านได้ · **ต้องแก้ไฟล์นี้แล้ว deploy จริงจึงจะหาย** ไม่ใช่ปล่อยให้วันหมดเขตจัดการ
- ไม่มีโปรไหนเปิดอยู่ ⇒ ส่วนโปรโมชันและปุ่ม "See promotions" บน hero หายทั้งคู่
- ไฟล์ผิดรูป (ช่องหาย · วันผิดรูป · `code` ซ้ำ · รูปไม่มีจริง) ⇒ `next build` ล้ม ⇒ deploy ไม่เกิด หน้าเว็บเดิมอยู่ต่อ
- ตรวจก่อน merge: `npm run build && npm run lint && npm run check:css && npm run check:assets` แล้วเปิดหน้าแรกดูจริง

## ช่องที่ระบบ KBOT แก้ได้ และเกณฑ์ตรวจ PR ของมัน (ตกลงกัน 2026-10-19 · `Q-KWEB-004` + ack `a9d0a48df`)

คุณคมเพชรสั่ง 19 ต.ค. ให้เพิ่มความสามารถของระบบ KBOT จนเปิด PR แก้ไฟล์นี้ได้เอง
ขอบเขตที่ทั้งสองห้องตกลงกันไว้ เขียนไว้ที่นี่ **ก่อน** PR ใบแรกจะมาถึง เพื่อให้เกณฑ์ตรวจมีอยู่ก่อน ไม่ใช่คิดตอนตรวจ

| ระดับ | ช่องที่ระบบแก้ได้ |
|---|---|
| รายโปร | `status` · `ends` · `ends_label` |
| ระดับไฟล์ | `note` · `updated_at` |

ช่องอื่นทั้งหมดระบบแตะไม่ได้ โดยเฉพาะ `title` `eyebrow` `detail` `points` `offer` `message` ซึ่งเป็นถ้อยคำของครูนก
PR ที่แตะช่องนอกรายการนี้ หรือเพิ่ม/ลบโปร ให้ตีกลับ ไม่ต้องถกเหตุผล

กติกาที่เหลือของ PR จากระบบ: เปิด PR เท่านั้น ไม่ merge เอง ไม่ push `main` ไม่ว่ากรณีใด ·
ห้องนี้รันสี่ด่านแล้วเปิดหน้าแรกดูจริงก่อน merge ทุกครั้ง · ถ้าระบบยังไม่มี token มันจะถอยไปตั้งงานส่งเนื้อไฟล์ให้คนพิมพ์ลงแทน

## ด่านปฏิทิน (เพิ่ม 2026-10-19 ตามที่ KBOT ขอใน `Q-KBOT-007`)

ด่านรูปไฟล์ 5 แบบเดิมมองไม่เห็นเรื่องที่ขึ้นกับวันที่ `lib/promotions.ts` จึงตรวจเพิ่มสองข้อตอน build
อยู่ในไฟล์เดียวกับตัวตรวจอื่น ไม่แยกสคริปต์ เพื่อไม่ให้สองที่เคลื่อนออกจากกัน

| เงื่อนไขที่ทำให้ `next build` ล้ม | ข้อความที่ได้ |
|---|---|
| โปรที่ `status: "live"` แต่เลยเที่ยงคืนท้ายวัน `ends` ไปแล้ว | ``P-XXX: `status` is still "live" but the offer ended on 2026-10-16 — set it to "ended"`` |
| มี `note` ที่ไม่ว่าง ทั้งที่ไม่มีโปรไหน `live` และยังไม่หมดเขต | ``(file): `note` is still set while no offer is live`` |

พิสูจน์ว่าด่านฟ้องจริง ไม่ใช่ด่านที่ผ่านตลอด: รันกับไฟล์ก่อนแก้ของวันที่ 19 ต.ค. (ซึ่ง `P-SAUNA90` และ `P-HAIRSPA10`
ยังเป็น `live` ทั้งที่ `ends` คือ 2026-10-16) build ล้มที่ `P-SAUNA90` ตามข้อความข้างบน แล้วผ่านเมื่อปิดสถานะทั้งสองใบ

ผลข้างเคียงที่ตั้งใจ: พอโปรหมดเขตแล้วยังไม่มีใครแก้ไฟล์ **deploy ทุกอย่างจะติดด่านนี้** จนกว่าจะแก้หนึ่งบรรทัด
รับไว้โดยรู้ตัว เพราะรอบเงียบของมันเพิ่งทำให้โปรที่หมดแล้วค้างบน production สามวัน
