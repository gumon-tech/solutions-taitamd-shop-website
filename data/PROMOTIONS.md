# โปรโมชันหน้าแรก — `data/promotions.json`

แก้โปรโมชันบนหน้าแรกได้โดยแก้ไฟล์นี้ไฟล์เดียว ไม่ต้องแตะโค้ด
ระบบ WhatsApp ของร้าน (shop system) เปิด PR แก้ไฟล์นี้เอง ทั้งเพิ่มการ์ดใหม่และปิดการ์ดเดิม แล้ว workflow merge เองเมื่อด่านผ่าน (หัวข้อท้ายไฟล์)
ชื่อช่องใช้ร่วมกับฐานข้อมูลของระบบร้าน ⇒ เปลี่ยนชื่อช่องต้องแก้ทั้งสองฝั่งพร้อมกัน

รีโปนี้เป็น public (วัด 2026-10-14 ด้วย `gh repo view`) ⇒ ทุกอย่างในไฟล์นี้ รวมโปร `draft` อ่านได้จากภายนอก
ที่ `raw.githubusercontent.com/.../main/data/promotions.json` (200 · 2,443 B) ⇒ ห้ามใส่สิ่งที่ยังไม่พร้อมให้ลูกค้าเห็น
ระบบร้านอ่านไฟล์นี้จาก URL นั้นเป็นทะเบียนโปร

## ระดับไฟล์

| ช่อง | ความหมาย |
|---|---|
| `updated_at` | เวลาที่แก้ล่าสุด ISO UTC (ไว้ให้คนอ่าน ระบบไม่ใช้ตัดสิน) |
| `note` | ประโยคใต้หัวข้อ ไม่บังคับ · ระวัง: ถ้าเขียนจำนวนโปรหรือวันหมดเขตไว้ ต้องแก้ให้ตรงทุกครั้งที่เพิ่มหรือถอดโปร<br>**ไม่มีโปร `live` = ถอดช่องนี้ออก หรือส่งเป็นสตริงว่าง `""`** สองรูปนี้ค่าเท่ากัน (ค่าที่มีแต่ช่องว่างก็นับว่าไม่มี) · ห้ามเก็บประโยคเก่าไว้ เพราะตอนไม่มีโปรมันไม่แสดง แล้วจะโผล่พร้อมโปรใหม่ใบแรก ตอนนี้มีด่านฟ้องแล้ว (ดูท้ายไฟล์) |
| `promotions` | รายการโปร เรียงตามลำดับที่แสดง |

## ระดับโปร (ทุกช่องต้องมี · `image` เป็น `null` ได้)

| ช่อง | ความหมาย |
|---|---|
| `code` | รหัสไม่ซ้ำ เช่น `P-SAUNA90` · ภาพใหม่ตั้งชื่อตามนี้ใน `public/images/campaigns/` |
| `title` `eyebrow` `detail` `offer` | ข้อความบนการ์ด · อ้างได้เท่าที่ใบปลิวหรือผู้สั่งงานให้มาเท่านั้น |
| `points` | ป้ายสั้นบนการ์ด (รายการข้อความ) |
| `message` | ข้อความ WhatsApp สำเร็จรูป · เว็บเติม `[web-C]` ให้เอง ห้ามใส่ป้ายเอง |
| `image` | path ใต้ `/images/` · ไฟล์ต้องอยู่ใน `public/` จริง · ตรวจขนาดก่อน commit (เว็บไม่ย่อรูปให้) · **`null` = การ์ดข้อความล้วน** ไม่มีภาพ ป้าย `eyebrow` ย้ายไปอยู่บนตัวการ์ด |
| `illustrative` | `true` เมื่อเป็นภาพสร้างที่มีการทำทรีตเมนต์ · `false` สำหรับภาพจริงของร้าน (กติกา LAW `D-W22`) |
| `starts` `ends` | วันที่ `YYYY-MM-DD` · แสดงตั้งแต่เที่ยงคืนต้นวัน `starts` ถึงเที่ยงคืนท้ายวัน `ends` เวลาลอนดอน |
| `ends_label` | วันหมดเขตแบบคนอ่าน เช่น `Friday 16 October 2026` |
| `status` | `live` แสดงตามช่วงวัน · `draft` ยังไม่แสดง · `ended` เก็บไว้เป็นประวัติ ไม่แสดง |

## พฤติกรรม

- โปรขึ้นและลงเองตามนาฬิกาของผู้เข้าชม ไม่ต้อง deploy ตรงวัน · แต่โปรที่ยังไม่อยู่ในไฟล์ตอน build จะไม่ขึ้นจนกว่าจะ deploy
- **ระวัง: "ซ่อนเอง" ไม่เท่ากับ "หายจากเว็บ"** — โปรที่ `status: live` และยังไม่หมดเขตตอน build จะถูกฝังลง HTML
  แล้วซ่อนด้วยนาฬิกาฝั่งผู้เข้าชม (`PromoGate`) ⇒ หลังหมดเขต ลูกค้าไม่เห็น แต่ HTML ยังแบกข้อเสนอที่หมดอายุไว้
  (วัด 2026-10-19: apex 182,265 B มีส่วนโปรทั้งก้อน · build ที่ปิดสถานะแล้ว 159,902 B ⇒ ต่างกัน ~22 KB)
  ⇒ crawler และคนที่ปิด JS ยังอ่านได้ · **ต้องแก้ไฟล์นี้แล้ว deploy จริงจึงจะหาย** ไม่ใช่ปล่อยให้วันหมดเขตจัดการ
- ไม่มีโปรไหนเปิดอยู่ ⇒ ส่วนโปรโมชันและปุ่ม "See promotions" บน hero หายทั้งคู่
- ไฟล์ผิดรูป (ช่องหาย · วันผิดรูป · `code` ซ้ำ · รูปไม่มีจริง) ⇒ `next build` ล้ม ⇒ deploy ไม่เกิด หน้าเว็บเดิมอยู่ต่อ
- เรื่องวันที่ไม่ทำให้ build ล้ม (ดูหัวข้อ "ด่านปฏิทิน")
- ตรวจก่อน merge: `npm run build && npm run lint && npm run check:css && npm run check:assets` แล้วเปิดหน้าแรกดูจริง

## การเปลี่ยนจากระบบร้าน (shop system)

ผู้บริหารร้านสั่งระบบ WhatsApp ของร้านในแชท ระบบเปิด PR จากสาขา `shop-agent/promotions-<id>` ที่แก้ `data/promotions.json` ไฟล์เดียว
แล้ว `.github/workflows/auto-merge-shop-agent.yml` merge เองเมื่อด่านผ่านทั้งหมด จากนั้นสั่ง workflow deploy (`nextjs.yml`) ไม่มีคนต้องกด merge

ระบบทำได้
- **เพิ่มการ์ดใหม่** ต่อท้ายรายการ ครบทุกช่องของตารางข้างบน (ห้ามมีช่องอื่น) `image` เป็นภาพที่มีอยู่แล้วใน `public/images/` หรือ `null`
- **ปิด เปิดใหม่ หรือเลื่อนวันจบของการ์ดเดิม** แก้ได้เฉพาะ `status` `ends` `ends_label` ของการ์ดที่มีอยู่ (draft→live · live→ended · ended→live ได้ทั้งหมด ผู้บริหารเป็นคนตัดสินผ่านแชท)
- แก้ `note` และ `updated_at` ระดับไฟล์ · ช่องระดับไฟล์อื่นนอกจาก `updated_at` `note` `promotions` ห้ามเพิ่ม

ด่านที่ workflow ตรวจ (ไม่ผ่านข้อใด PR ค้างไว้ให้คน และมีคอมเมนต์บอกว่าล้มที่ขั้นไหน ระบบร้านอ่านแล้วแจ้งผู้บริหาร)
1. ชื่อสาขาเป็น `shop-agent/promotions-*` และ PR แก้ `data/promotions.json` ไฟล์เดียว ไม่แตะโค้ด สคริปต์ หรือ workflow
2. `npm run test:shop-agent` (เทสต์ของกติกาข้อ 4 เอง รันด้วยสคริปต์ของ main) · `check-orphan-assets` · `next build` (ด่านรูปไฟล์ทั้งหมดใน `lib/promotions.ts`) · `npm run lint` · `npm run check:css`
3. ตอนจะ merge `main` ต้องยังเป็น commit เดียวกับที่ด่านตรวจ ถ้า `main` ขยับไปแล้ว ไม่ merge และคอมเมนต์ `stage=merge` ว่า main ขยับ ระบบร้านสร้างสาขาใหม่จาก main ล่าสุด ด่านจะรันใหม่เอง
4. `scripts/check-shop-agent-diff.mjs promotions`
   - การ์ดเดิมห้ามหาย ห้ามย้ายลำดับ ห้ามแก้ถ้อยคำ (แก้ได้แค่ `status` `ends` `ends_label`) · `ends_label` ที่แก้ต้องผ่านกติกาเนื้อหาและยาวไม่เกิน 40
   - การ์ดใหม่ต่อท้ายเท่านั้น · `code` รูป `P-AB12` · ความยาว title 80 eyebrow 60 detail 400 offer 160 message 200 ends_label 40 · points ไม่เกิน 4 ป้าย ป้ายละ 60
   - `image` ต้องเป็น `null` หรือรูป `/images/<โฟลเดอร์>/<ชื่อ>.jpg|.jpeg|.png|.webp` ตัวพิมพ์เล็ก ไม่มี `..` และเป็นไฟล์จริงใน `public/images/`
   - `illustrative` ต้องตรงกับการ์ดบน main ที่ใช้ภาพเดียวกัน · ภาพที่ยังไม่เคยมีการ์ดใช้ ต้องเป็น `true` (ภาพร้านจริงที่จะติด `false` ครั้งแรก ให้คนเป็นคนตั้ง)
   - `note` ที่แก้ ยาวไม่เกิน 200 และผ่านกติกาเนื้อหาชุดเดียวกับการ์ด
   - กติกาเนื้อหา (ตรวจบนรูป NFKC ก่อน ตัวอักษรกว้างหรือตัวหนาแบบคณิตศาสตร์จึงหลบไม่ได้):
     ไม่อ้างผลต่อสุขภาพ (รายการคำตาม ASA/CAP สำหรับงานนวด) · ไม่มีชื่อคนในทีม (`data/team.json`) หรือรหัสพนักงาน ·
     ไม่มีลิงก์ ทั้งแบบมี `https://` `www.` และโดเมนเปล่า (`example.co.uk` · `bit.ly/x` · `dot com`) · ไม่มีอีเมล ·
     ไม่มีเบอร์โทร รวมตัวเลขที่เว้นวรรคหรือคั่นด้วย `- . / ( )` ติดกันตั้งแต่ 9 หลัก (ตัวเลขที่ติดตัวอักษรหรือ `£` เช่น `90-minute` `£35` ไม่นับ) ·
     ไม่มีอีโมจิ อักษรไทย หรืออักษรนอกภาษาอังกฤษ (ยอมเฉพาะ ASCII อักษรละตินมีเครื่องหมาย และ `£ € ’ ‘ “ ” · – — … ° ×`) ·
     ไม่มีอักขระล่องหน (zero-width · bidi) หรืออักขระควบคุม · ไม่มีป้าย `[web-` · ไม่มีคำเดียวยาวเกิน 24 ตัวอักษร (ล้นการ์ดบนมือถือ)
   กติกาชุดนี้ควรตรงกับที่ระบบร้านตรวจก่อนเปิด PR ⇒ ปกติด่านนี้ไม่ควรล้ม ถ้าล้มแปลว่าสองฝั่งเคลื่อนออกจากกัน
   (ข้อควรรู้: กติกาที่เพิ่ม 2026-11 เข้มกว่าเดิม ระบบร้านต้องปรับตามให้ตรง)

ถ้อยคำของการ์ดที่คนเขียน (PR ที่ไม่ได้มาจากสาขา `shop-agent/`) ไม่ผ่านด่านข้อ 4 และยังต้องมีคนตรวจและ merge ตามเดิม
สำหรับ PR ของคน ด่าน `site-check` ใน workflow นี้ไม่รันโค้ดของ PR เลย (กันการวางแคชผ่าน `pull_request_target`) ผ่านเองทันที
ส่วนการ build และวัดผลของ PR คนอยู่ที่ `visual-gate.yml` ตามเดิม

## build.json

หลัง `next build` workflow deploy (`nextjs.yml`) เขียน `out/build.json` ด้วย `scripts/write-build-json.mjs` (`npm run build:json`)
`{ "sha": commit ที่ build, "built_at": เวลา UTC, "data": { "<ชื่อไฟล์>": sha256 ของ data/<ชื่อไฟล์>.json } }` ช่องชื่อเดียวกับเว็บ Sri Siam
ระบบร้านอ่าน `https://taitam-d.com/build.json` เพื่อยืนยันว่าสิ่งที่ merge ขึ้นเว็บจริงแล้ว (sha ตรงกับ merge commit หรือ hash ของไฟล์ตรง)

## ด่านปฏิทิน

เรื่องที่ขึ้นกับวันที่ **ไม่ทำให้ `next build` ล้ม** เพราะถ้าล้ม เวลาที่ผ่านไปเฉย ๆ จะทำให้ deploy ทุกอย่างติด
รวมถึงการ์ดใหม่จากระบบร้าน จนกว่าจะมีคนแก้ไฟล์ด้วยมือ

| เงื่อนไข | สิ่งที่ build ทำ |
|---|---|
| โปรที่ `status: "live"` แต่เลยเที่ยงคืนท้ายวัน `ends` ไปแล้ว | ถือว่าจบแล้ว ไม่ใส่ลง HTML · พิมพ์คำเตือนใน log ของ build |
| มี `note` ที่ไม่ว่าง ทั้งที่ไม่มีโปรไหน `live` และยังไม่หมดเขต | ไม่แสดง `note` · พิมพ์คำเตือน |

ระบบร้านตั้ง `status: "ended"` เองในไฟล์รอบถัดไปที่เปิด PR · ถ้ายังเห็นคำเตือน แก้ไฟล์ให้ตรงได้ตามปกติ
