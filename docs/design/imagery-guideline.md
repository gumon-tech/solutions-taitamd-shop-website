# ไกด์ไลน์ภาพประกอบของเว็บร้าน

> เจ้าของสั่ง 2026-09-12 และย้ำว่าเคยสั่งไปแล้วรอบหนึ่ง (คิว W-40 · มติถาวร T18)
> ไฟล์นี้คือขั้นที่ 2 ของคำสั่ง คือศึกษาแนวทางก่อนหยิบภาพ ไม่ใช่หยิบภาพก่อนแล้วค่อยหาเหตุผล

## 1 หลักข้อเดียวที่ตัดสินทุกภาพ

**หน้าบริการต้องแสดงบริการที่กำลังเกิดขึ้น ไม่ใช่ห้องที่บริการนั้นเกิดขึ้น**

ถ้อยคำเจ้าของ verbatim
> "ถ้าเอาแต่ภาพสถานที่อย่างเดียว อย่างเช่นสระผมงี้ ทำหน้างี้ แล้วเจอแต่เตียง
> มันแปลกๆ นะครับ เหมือนขายเตียงอะ ไม่เหมือนคลินิคเลย"

แนวทางของอุตสาหกรรมตรงกับที่เจ้าของพูด แหล่งอ้างอิงอยู่ท้ายไฟล์ สาระคือ
ภาพที่แสดงการให้บริการจริงโดยคนของร้าน สร้างความเชื่อได้มากกว่าภาพสต็อกหรือภาพห้องเปล่า
และแต่ละบริการควรมีภาพของตัวเอง เพื่อให้ผู้อ่านเห็นตัวเองอยู่ในภาพนั้น

**เกณฑ์ตัดสินหน้างาน** เปิดภาพแล้วถามว่า ภาพนี้ขายอะไร
ถ้าคำตอบคือเตียง โคมไฟ ขวดยาทาเล็บ หรือผ้าเช็ดตัว แปลว่าภาพยังไม่ผ่าน
ถ้าคำตอบคือการนวด การสระผม การทำเล็บ แปลว่าผ่าน

## 2 ผลสำรวจ วัดจาก HTML ที่ build จริง 2026-09-12

นับ `<img>` จากไฟล์ใน `out/` ไม่ได้นับจากซอร์ส เพราะภาพส่วนใหญ่มาจากคอมโพเนนต์
ไม่ใช่จากไฟล์ของหน้า และการนับจากซอร์สจะรายงานหน้าแรกว่ามี 0 ภาพ

| หน้า | จำนวน img | ภาพตกแต่งจริง |
|---|---|---|
| `/massage-kings-cross/` | 1 | 0 |
| `/deep-tissue-massage-kings-cross/` | 1 | 0 |
| `/facial-kings-cross/` | 1 | 0 |
| `/nails-kings-cross/` | 1 | 0 |
| `/lash-extensions-kings-cross/` | 1 | 0 |
| `/waxing-kings-cross/` | 1 | 0 |
| `/book/` | 2 | 0 |
| `/` | 26 | มี |
| `/tour/` | 15 | มี |
| `/services/` | 12 | มี |
| `/signature/` | 8 | มี |
| `/story/` | 4 | มี |

เลข 1 ในคอลัมน์กลางคือโลโก้บนหัวเว็บ ไม่ใช่ภาพประกอบ เลข 2 ของ `/book/` คือโลโก้กับรูป QR
หน้าเอกสารอย่าง `/privacy/` และ `/cookies/` ไม่นับ

**หกหน้าที่ว่างเปล่าคือหกหน้าที่ Google Ads ยิงเงินเข้าโดยตรง** จึงไม่ใช่หน้ารอง

## 3 ของที่มีอยู่แล้ว และเหตุที่ยังใช้แทนไม่ได้

ในรีโปมีภาพ 76 ไฟล์ รวม 12 MB และ **24 ไฟล์ไม่ถูกอ้างถึงจากโค้ดเลย**
ในจำนวนนั้นมีชุดที่ตั้งชื่อตรงกับหกหมวดบริการพอดี

```
public/images/services/card/massage.jpg   720x480   50 KB
public/images/services/card/facials.jpg   720x480   52 KB
public/images/services/card/hair.jpg      720x480   36 KB
public/images/services/card/nails.jpg     720x480   41 KB
public/images/services/card/lashes.jpg    720x480   63 KB
public/images/services/card/waxing.jpg    720x480   58 KB
```

เปิดดูครบทั้งหกไฟล์แล้ว **ทั้งหกเป็นห้องเปล่าหรือภาพนิ่งของอุปกรณ์ ไม่มีคนอยู่ในภาพเลยสักไฟล์**

```
massage   เตียงนวดปูผ้าเรียบร้อย ไม่มีคน
facials   เตียงกับถาดครีมและลูกกลิ้ง ไม่มีคน
waxing    เตียงกับผ้าเช็ดตัวและกระปุก ไม่มีคน
hair      เก้าอี้กับกระจกและแปรง ไม่มีคน
nails     ขวดยาทาเล็บเรียงบนโต๊ะกับผ้าเช็ดตัว ไม่มีคน
lashes    แหนบกับถาดขนตาวางบนผ้า ไม่มีคน
```

เท่ากับว่าของที่มีอยู่ **คือตัวอย่างของปัญหาที่เจ้าของทักพอดี ไม่ใช่ทางแก้**
เอาขึ้นหน้าเว็บได้ทันทีก็จริง และจะทำให้ตัวเลขจำนวนภาพดูดีขึ้นทันที
แต่มันจะแก้เลขโดยไม่แก้เรื่อง และเรื่องคือสิ่งที่เจ้าของพูดถึง

## 4 แหล่งภาพที่ใช้ได้ เรียงตามลำดับที่ควรหยิบ

1. **ภาพถ่ายจริงของร้าน** ใช้ได้เต็มที่ บรรยายว่าเป็นร้านของเราได้
2. **ชุด Treatwell 12 ไฟล์** เจ้าของยืนยันแล้วว่าเป็นภาพของร้านเอง
   ยกเว้น `treatwell-14715041` (ป้ายสะกดเก่า D-71) และ `treatwell-14715891` (พรมลายธนบัตร)
3. **ภาพที่สร้างด้วย Gemini มีหน้าคนได้** เจ้าของเคาะเอง 2026-09-12 และ WS รับเป็นมติถาวร T18

## 5 กติกาคำบรรยาย ข้อเดียวที่ยังบังคับกับภาพที่สร้างด้วย AI

เจ้าของอนุญาตเรื่อง **การใช้ภาพ** ส่วนมติ D-W22 คุมเรื่อง **การเรียกภาพนั้นว่าอะไร**
สองอย่างนี้คนละเรื่องกัน จึงไม่ขัดกัน และ WS อ่านตรงกันแล้ว

- ภาพที่สร้างด้วย AI ใช้เป็นภาพประกอบได้ทุกหน้า มีหน้าคนได้
- `alt` และคำบรรยาย **ห้ามอ้างว่าเป็นห้องของเรา ช่างของเรา หรือลูกค้าจริงของเรา**
- เขียน `alt` ให้บรรยายสิ่งที่เห็น ไม่ใช่อ้างความเป็นเจ้าของ
  ใช้ได้ `Close-up of a manicure in progress`
  ห้ามใช้ `Our technician working on a client at Taitam-D`
- ภาพถ่ายจริงของร้าน บรรยายว่าเป็นร้านได้ตามปกติ

## 6 ข้อจำกัดทางเทคนิคของรีโปนี้ ซึ่งต่างจากเว็บทั่วไป

**`next.config.mjs` ตั้ง `images: { unoptimized: true }`** เพราะ static export บังคับ
แปลว่า Next ไม่ย่อภาพ ไม่แปลงฟอร์แมต และไม่สร้างขนาดสำรองให้เลย
ภาพที่วางลงไปคือภาพที่ผู้ใช้โหลดจริง ทุกไบต์

ผลที่ตามมาสามข้อ

- **ต้องย่อและเลือกฟอร์แมตเองก่อน commit** แนวทางสากลคือภาพเนื้อหาไม่เกิน 150 KB
  และภาพใหญ่เต็มความกว้างไม่เกิน 200 KB ชุด `services/card` ที่มีอยู่ (36 ถึง 63 KB) อยู่ในเกณฑ์
- **ขนาดที่ใช้จริงต้องใกล้ขนาดไฟล์** กฎเหล็กข้อ 3 ของรีโปเกิดจากโลโก้ 2.4 MB ที่แสดงจริง 44x44 px
- **เพดานน้ำหนักของงานหน้าตาชุดนี้คือสะสมไม่เกิน 15% จากฐาน 176,012 ไบต์**
  ใช้ไปแล้ว 3.0% ณ 2026-09-12 เหลือประมาณ 21 KB ต่อหน้าแรก
  หน้า landing แต่ละหน้ามีงบของตัวเอง เพราะคนละหน้า แต่ต้องประกาศตัวเลขก่อนและหลังทุกครั้ง

## 7 กติกาโทนสีที่ภาพต้องผ่าน ไม่ใช่แค่สวย

- **ห้ามใส่เงาไล่เฉดหรือ overlay ทับภาพเพื่อให้ตัวอักษรอ่านออก** (T11)
  ถ้าต้องมีตัวอักษรบนภาพ ให้ตัวอักษรมีพื้นของตัวเองเป็นชิปทึบ
  ทำแล้ว 2 ที่ในการ์ดโปรโมชัน ได้ 5.72 และ 12.44 ซึ่งรูปใหม่ในอนาคตเปลี่ยนค่าไม่ได้
- **พื้นที่สว่างของหน้าห้ามลด** วัดด้วย `scripts/brightness-probe.js` ก่อนและหลังทุกครั้ง
  ภาพที่มืดกว่าพื้นหน้าเดิมจะดึงตัวเลขนี้ลง แม้หน้าจะดูดีขึ้น ดังนั้นเลือกภาพที่สว่าง
- **ตัวอักษรทุกจุดต้องผ่าน AA** วัดด้วย `scripts/contrast-probe.mjs` ที่ 1440 และ 375
  เครื่องมือต้องพิมพ์ค่าควบคุม 2 ตัวตรงก่อน ไม่ตรงคือผลทั้งรอบใช้ไม่ได้

## 8 แบบวางภาพสำหรับหน้า landing หกหน้า

หกหน้านั้นโครงเหมือนกัน คือหัวเรื่อง ย่อหน้าอธิบาย ปุ่ม WhatsApp แล้วตามด้วยเนื้อหายาว
ที่ขาดคือภาพที่ทำให้ผู้อ่านเห็นว่ากำลังจะได้อะไร ข้อเสนอคือ

1. **ภาพเดียวต่อหน้า วางใต้ปุ่ม WhatsApp ก่อนเนื้อหายาว** เห็นได้ในจอแรกบนเดสก์ท็อป
   และเห็นทันทีหลังเลื่อนครั้งเดียวบนมือถือ
2. **สัดส่วน 3:2 แนวนอน** ตรงกับชุดที่มีอยู่ 720x480 จึงเปลี่ยนภาพภายหลังได้โดยไม่ขยับเลย์เอาต์
3. **ภาพต้องแสดงบริการของหน้านั้นกำลังเกิดขึ้น** ตามข้อ 1
4. **ไม่ใส่ตัวอักษรทับภาพ** ที่หน้านี้ไม่จำเป็น และเลี่ยงปัญหาความต่างสีทั้งหมดไปได้
5. `loading` ปล่อยตามค่าเริ่มต้น ไม่ต้องใส่ `lazy` กับภาพที่อยู่ใกล้จอแรก

## 9 รายการภาพที่ต้องสร้างใหม่ พร้อมสิ่งที่ต้องเห็นในภาพ

ทั้งหกภาพต้องเป็นโทนเดียวกับร้าน คือเขียวเข้ม ไม้ ทองด้าน ครีม แสงธรรมชาตินุ่ม

| หน้า | สิ่งที่ต้องเห็น |
|---|---|
| massage | มือช่างกำลังนวดบ่าหรือหลังผู้รับบริการ เห็นผ้าคลุม เห็นว่ากำลังนวดอยู่ |
| deep-tissue | มือกำลังกดกล้ามเนื้อน่องหรือหลังส่วนล่าง น้ำหนักมือชัดกว่าแบบผ่อนคลาย |
| facial | มือกำลังทาครีมหรือนวดหน้าให้ผู้รับบริการที่นอนอยู่ เห็นใบหน้าได้ |
| nails | มือลูกค้าวางบนโต๊ะ มือช่างกำลังตะไบหรือทาเล็บ เห็นสองมือในภาพ |
| lashes | ช่างกำลังต่อขนตาให้ผู้รับบริการที่หลับตา เห็นแหนบกับมือช่าง |
| waxing | มือช่างกำลังทาแว็กซ์ที่ขาหรือแขน เห็นแถบผ้า ไม่ต้องเห็นใบหน้า |

ภาพที่มีอยู่เดิมหกไฟล์ **เก็บไว้ใช้เป็นภาพประกอบรองได้** เช่นวางคู่กับหัวข้อย่อยในหน้าเดียวกัน
เพราะภาพนิ่งของอุปกรณ์ทำหน้าที่นั้นได้ดี สิ่งที่มันทำไม่ได้คือเป็นภาพหลักของหน้าบริการ

## 10 รายการตรวจก่อน commit ทุกภาพ

```
ภาพนี้ขายอะไร ตอบว่าบริการ ไม่ใช่เฟอร์นิเจอร์
ขนาดไฟล์ไม่เกิน 150 KB และขนาดพิกเซลใกล้ขนาดที่แสดงจริง
alt บรรยายสิ่งที่เห็น และถ้าเป็นภาพ AI ไม่อ้างว่าเป็นห้อง ช่าง หรือลูกค้าของเรา
วัดพื้นที่สว่างก่อนและหลัง ต้องไม่ลด
ถ้ามีตัวอักษรบนภาพ ตัวอักษรต้องมีพื้นทึบของตัวเอง และวัด AA ที่ 1440 กับ 375
ไม่มีเงาไล่เฉดทับภาพเพิ่ม
น้ำหนักหน้าก่อนและหลัง ประกาศเป็นตัวเลข
```
